# Выпуск D2S

Откройте **Actions → D2S release → Run workflow**, укажите версию, например `0.1.1`.
Workflow собирает ARM64, ARMv7, MIPSel, запускает бинарники под QEMU, упаковывает комплект и подписывает `latest.json` ключом из секрета `D2S_ED25519_PRIVATE_KEY`. При ошибке любой архитектуры публикация не выполняется.

Перед запуском обновите `docs/release-notes.md`. Идентификатор выпуска: `d2s-v<версия>`. Повторно использовать опубликованный тег нельзя. Для отката выпускают новую версию с возвращённым кодом: архивы под старым тегом не подменяют.

Публичный ключ: `docs/d2s-release-public.pem`. Его копия закреплена в `scripts/install.sh` и `files/d2k-update.sh`. Закрытый ключ не хранится в репозитории, артефактах сборки или журнале. Изменение публичного ключа требует отдельной процедуры миграции доверия.

Локально: `ARCHES='arm64 arm mipsel' RELEASE_ID=d2s-v0.1.1 VERSION=0.1.1 ZIG=/path/to/zig sh scripts/build-router.sh`, затем `ARCHES='arm64 arm mipsel' RELEASE_ID=d2s-v0.1.1 sh scripts/package-release.sh builds release-out`.

Зелёные проверки CI подтверждают сборку, локальные тесты и запуск программ под эмуляцией. Они не заменяют проверку сайтов, файлов и звонков на реальном роутере. Ограничения первого стенда перечислены в README.
