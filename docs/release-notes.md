D2S 0.3.3 — второй этап оптимизации классификатора.

- Убраны повторы после достаточного положительного ответа: контроль TLS 1.2 и проверка разреза с длинной паузой завершаются после первого успеха. Полностью отрицательные вопросы проходят все повторы, три целевых рукопожатия сохранены.
- CLI-классификатор показывает время каждого наблюдения, отдельно целевую и контрольную проверки ответного направления. Количество проб учитывает фактически выполненные соединения, повторно используемая база не получает новую сетевую стоимость.
- Общие сетевые сроки, параллелизм, критерии подтверждения плана, правила перехвата и обработка Telegram/WhatsApp не менялись.
- Исправлено смещение подложки выбранного пункта меню: она следует за переносами строк и загрузкой шрифта. При изменении геометрии прежняя анимация больше не возвращает подложку к старым координатам.

Проверки: полный Linux-набор detect, целевые проверки с ASan/UBSan, 64 комбинации исходов без изменения итогового вердикта, отрицательные и неизмеренные ответы. На ARM64-стенде старый/новый алгоритмы сравнены на одном IP и одинаковом ClientHello в порядке ABBA: GitHub 1540 → 1191,5 мс, example.com 1089 → 940,5 мс по медиане; 7 соединений вместо 9. Это небольшая выборка прямой ветки, не процент ускорения всего поиска. Подробности: docs/field/2026-11-05-performance-stage2.md.

На стенде владелец подтвердил новое видео YouTube с перемоткой, отправку файлов Telegram и WhatsApp и ровное меню после Ctrl+F5 при выключенном верхнем обходе. Время долгих отрицательных поисков ещё не сокращено. Telegram Web остаётся отдельной нерешённой задачей. keenetic-doq и настройки сохраняются.
