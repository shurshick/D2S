D2S 0.3.4 — третий этап оптимизации: быстрее начальная TCP-база.

- Три независимые начальные TCP-пробы ожидают ответ одновременно. Число повторов, сроки подключения/ответа, адрес, ClientHello и правила оценки сохранены. На стенде отрицательный начальный вопрос сократился с 18,24 до 6,09 с. Это ускорение одной фазы, не всего подбора.
- Оптимизация включена для предварительной базы контроллера с числовым IPv4/IPv6. Свойства, проверка планов и запасной перебор выполняются как прежде. CLI сохраняет последовательное поведение по умолчанию; сравнение доступно через --parallel-base.
- Дополнительно создаются максимум два временных потока на активную базу. При нехватке ресурсов выполняются последовательно только ещё не начатые пробы. Уже отправленные не повторяются; ошибки собираются по номеру пробы, обработчики вызываются исходным работником, все потоки завершаются до возврата результата.
- Перехват, PPE, DNS, keenetic-doq и обработка Telegram/WhatsApp не изменены. На стенде добавилось около 24–40 КиБ занятой RAM на длинном базовом вопросе; резерв виртуальных стеков больше и отдельно описан в полевом отчёте.

Проверки: 27 комбинаций успеха/тишины/локальной ошибки, порядок ошибок, отказы создания потоков, несколько групп повторов, отмена, повторное использование базы, реальные IPv4/IPv6-сокеты. Полный detect check, ASan/UBSan и TSan прошли; новые проверки также прошли под QEMU ARM64/ARMv7/MIPSel. Полевой ABBA: 12 запусков на трёх адресах, во всех сохранены исходы и по три соединения. Подробности: docs/performance-stage3.md и docs/field/2026-11-06-performance-stage3.md.

Владелец подтвердил на 0.3.4-test1 YouTube с перемоткой и отправку файлов в Telegram/WhatsApp при выключенном верхнем обходе. Полный долгий запасной перебор этим выпуском не ускорен. Telegram Web остаётся отдельной нерешённой задачей.
