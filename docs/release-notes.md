D2S 0.3.2 — панель Telegram и исправления разделения протоколов.

- Перенесены свежие статусы и схема Telegram из t0fox/d2o 1cc424e с оформлением D2S: готовое соединение отличается от подтверждённого ответа, текущий отказ — от старого предупреждения, отсутствие статистики — от нуля.
- Коробки с явным пустым списком целей скрыты. Сохранённые планы не удаляются; неполные данные показываются как «цели не получены». Счётчики и ссылки семейств обновляются вместе.
- HTTPS браузера больше не отвергается как ошибочное MTProto-приветствие. TLS проходит к исходному серверу без расшифровки и подмены сертификата. Проверенный MTProto обрабатывается первым.
- Удалено старое исключение telegram.org, предполагавшее наличие VPS-туннеля для всех сайтов Telegram. Сайты допускаются к обычному подбору в своём протоколе.
- Собственные измерения и проверки плана сохраняют исходный сервер и TCP-кортеж: они исключены из локального MTProto-перехвата по меткам из настроек. LAN-перехват, диапазоны адресов и PPE сохранены.
- HTTPS не создаёт подтверждённые ответы, отказы или охлаждения MTProto. Сохранены исправления ожиданий планировщика и обработки WhatsApp из 0.3.1.

Проверки: полная регрессия core/datapath/detect и GitHub CI, проверки Telegram с ASan/UBSan, модель правил IPv4/IPv6 и конфигурации меток, панель в Chrome. На ARM64-стенде владелец подтвердил YouTube на test1 и работу Telegram/WhatsApp после транспортного изменения test2. keenetic-doq не изменён. ARMv7/MIPSel проверяются сборкой и QEMU, физических испытаний этих моделей нет.

Ограничение Telegram Web на проверенном маршруте остаётся: SYN выходят через WAN стенда, ответов от сервера нет; отдельная прямая TCP-проба не соединилась за 16 секунд. DNS подтверждён независимым DoH, обычный HTTPS работает. Сбой за пределами локального прокси не локализован между шлюзом и каналом; другого контрольного маршрута у владельца нет. Полная разблокировка Telegram Web этим выпуском не заявляется.
