# Проверка обновлений не помещалась в срок действия панели

08.11.2026 основной Keenetic не скачивал latest.json с GitHub. Прямые IPv4
и HTTP/1.1 запросы завершались тайм-аутом без данных; запрос к API с роутера
вернул HTTP504. Это наблюдение доступности сети, не доказательство причины DPI.

Отдельный дефект продукта: panel/server.c завершает команду через 60 секунд,
а один metadata fetch ждал до 120 секунд. После прекращения процесса
update.json оставался busy=checking, блокируя кнопки панели.

Исправление files/d2s-update.sh:

- Metadata и подпись получают по 12 секунд на одну попытку. Даже при двух
  файлах и proxy/direct fallback суммарный сетевой максимум48секунд; остаётся
  время для проверки подписи и записи ошибки до60секунд.
- Прямое подключение, как и прокси, ограничено8секундами.
- Архив сохраняет отдельный600-секундный бюджет. Подпись, хеш, откат и
  ограничения ночного окна не менялись.

Новый тест ограничивает допустимый metadata budget, падает на исходных120
секундах и проходит после правки. Весь scripts/test-update.cjs PASS: подпись,
отказ подделки, установка, возврат, proxy/direct fallback и ночное окно.
sh -n, node --check, namespace и diff --check PASS.

На основном сначала через SSH передан точный подписанный комплект0.5.2.
Временный локальный адаптер принимал только три точных официальных URL
(metadata, подпись, ARM64-архив), штатный updater самостоятельно проверил
Ed25519 и SHA256. Новые компоненты не смешивались с0.5.1. Все семь бинарников
сверены с архивом, оба peer ready, resolver/observer работают, config byte-exact,
все прежние plan_id сохранены, frozen=false. После независимой проверки
состояние завершено идемпотентной командой установки уже установленного0.5.2.

Затем установлен только исправленный updater. Живая неудачная сетевая
проверка уложилась в предел панели и сбросила busy. Для панели восстановлена
проверенная подписанная metadata0.5.2; временный адаптер и переданные архивы
удалены. Настройки прокси и системной сети не добавлялись. Закреплённая
подпись не отключалась. На роутере остались приватные резервные данные.

Ограничения: правка устраняет зависание проверки, но не чинит доступ к
GitHub. При продолжающейся недоступности новые сетевые проверки покажут ошибку.
Архивы публичного0.5.2 неизменны; исправление updater находится в main и
локально на основном, до следующего выпуска.
