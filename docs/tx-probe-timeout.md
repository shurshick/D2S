# TX timeout не является измеренным обрывом объёма

14.11.2026, журнал Fallout 76: три узла p76prod.systems, TLS 1.2. После
нескольких HEAD с X-Pad TX-зонд не дождался следующего TLS record header.
Независимый GET получил полный HTTP 404, тело 9/9. Код volume.c превращал
любую ошибку после порога в D2S_VOL_CUT; номинальная ступень 4 * 4000 / 1024
печаталась как «обрыв 15 КБ». Затем она участвовала в поиске коробки и плана.
probe-confirmed при live=unknown не доказывал работоспособность игры.

Исправление ограничено конкретно воспроизведённым дефектом:

- TLS 1.2/1.3 выставляют errno=ETIMEDOUT при истечении read deadline.
- drain_head_tls различает deadline и другие ошибки без разбора текста.
- drain_head_plain также отличает timeout от закрытия/ошибки и повторяет
  прерванный poll/recv в пределах исходного deadline.
- TX timeout после первых успешных ступеней возвращает D2S_VOL_SHORT:
  бюджет обрыва не измерен. Он больше не создаёт TX-примету volume.
- Независимый подтверждённый парный RX-обрыв сохраняется. Обработка reset,
  завершённых ответов и остальных протоколов этим изменением не подменяется.

Регрессия test_volume_context воспроизводит четыре HEAD-ответа и отказ на
пятой ступени при полном коротком 404. До правки timeout ошибочно давал CUT;
после — SHORT. Оба TLS-профиля проверяются отдельно. Контрольный ECONNRESET
сохраняет прежний CUT, а парный RX cut не пропадает из-за TX timeout.
test_verify проверяет ETIMEDOUT на реальных локальных socketpair для обоих
TLS-клиентов, без внешних сайтов. Фикстуры и ASan/UBSan проходят.

Ограничения: журнал не содержит достаточного доказательства точной причины
сбоя реальной игры. Повторяемость истинного TX-обрыва, серверные ограничения
HEAD/X-Pad и полноценный игровой обмен требуют отдельной полевой проверки.
Старые каталожные привязки не удаляются автоматически. Эта правка не является
заявлением об исправленном входе в Fallout 76.
