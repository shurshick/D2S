# Telegram: обновление панели и записи без целей

## Источник и границы переноса

Источник — t0fox/d2o, `1cc424ea75a3860701d76075231a067174384b5a`.
Сверка с ранее использованной базой `fd4e262`: коммиты `a03f46a`,
`cf0aae8`, `1cc424e`. Перенесены интерфейс, модель статусов, связанные
проверки и значение `TG_ROUTE_NONE` для отказа до выбора маршрута.
Последнее не меняет выбор или исполнение сетевого маршрута.

Перенос отличает готовое соединение от ответа Telegram, текущую ошибку от
предыдущего отказа, отсутствие статистики от нулевых значений. Добавлены
краткие состояния маршрутов/DC, время последнего ответа и предупреждения,
сворачиваемая схема. Палитра D2S и порядок карточек поиска сохранены.
Тест цвета использует реальный цвет темы, а не оттенок исходной панели.
Активный JS API называется `D2STelegramFlow`; проверка пространства имён
теперь замечает и смешанный регистр.

REA среди доступных инструментов отсутствовал. Поэтому обязательную
проверку через REA выполнить не удалось; вместо неё использованы закреплённый
git diff и трёхстороннее слияние. Это ограничение процедуры, а не свидетельство
REA. Журнал прямой сверки `UPSTREAM-PANEL-20261105-1cc424e` с SHA-256 файлов:
[../provenance/upstream-panel-1cc424e.json](../provenance/upstream-panel-1cc424e.json).
Не переносились старый handoff и конфигурация браузера с путём к Brave
на компьютере автора. Донорские исходники не редактировались.

## Почему появляется коробка без целей

`core/sched.c:forget_clear_target_bindings()` снимает привязку после двух
независимых успешных прямых замеров, сохраняя планы и отпечаток коробки.
Перенос доказательства QUIC/ECH с имени на адрес также снимает прежнюю
привязку. Само наличие плана поэтому не означает наличие текущих целей.

Публикация `boxes[].bindings` в `core/sched.c` перечисляет все привязки,
включая выключенные и перепроверяемые. Панель считала длину именно этого
списка: группировка целей по семействам число не уменьшала. Отдельного
серверного фильтра, который превращал бы непустой список в ноль, не найдено.

Теперь модель панели скрывает запись, только если `bindings` — явный пустой
массив. Каталог и сохранённые планы не меняются. Если список не получен
(`null`/отсутствующее поле), запись остаётся видимой с «— / цели не получены».
Именные и адресные цели, перепроверка и покрытие семействами не скрывают коробку.
Счётчик и номера коробок используют ту же модель; ссылки семейств обновляются
при изменении видимых коробок. Когда остались только планы без привязок,
панель сообщает «Коробок с целями пока нет», не объявляя каталог пустым.

Конкретная запись «Коробка 13» со скриншота пока не сопоставлена с каталогом
устройства. При чтении стенда 192.168.31.1 обнаружен оригинальный d2o
`d2o-20261105-0555-1cc424e`, каталог пуст. Установка D2S на стенде отсутствует.
Адрес панели со скриншота запрошен у владельца; основной роутер не затрагивался.

## Проверки и незакрытое

- Новый `panel/test_empty_boxes.cjs` воспроизвёл показ явной пустой записи
  до правки, после правки проходит. Проверяет сохранность исходных данных,
  IP-цели и различие между пустым и отсутствующим списком.
- `make -C panel test`: модель, HTTP/CLI и существующие проверки проходят.
- `make -C telegram test`: весь набор проходит, включая состояние отказа
  до выбора маршрута. Транспортные изменения в этот перенос не входят.
- Браузерная проверка: настоящий C-сервер с изолированными данными, сохранение
  планов в API при скрытии в DOM, смена пустого/неполного/полного снимка,
  ссылки семейств, текущие статусы Telegram и адаптивная раскладка.
  Локально Node 18 использует установленный `undici.WebSocket` только в
  тестовой обёртке; штатный CI рассчитан на Node 22.

Telegram Web остаётся отдельной неисправностью. Сброс воспроизведён браузером
и curl на текущем оригинальном d2o стенда. Статический разбор обнаружил
перенаправление HTTPS-адреса Web в MTProto-прокси и общий запрет подбора для
поддоменов telegram.org. Это ещё не полевое доказательство исправления;
новая панель не объявляется решением Telegram Web. Подмена установленного
на стенде d2o без ответа владельца не выполнялась; keenetic-doq не менялся.
