# Шесть изменений алгоритмов и аудит 0.4

База — 0.3.5, `cdb192e`. Шесть этапов реализованы отдельными коммитами
`bd1c9de`, `3f0b511`, `99bc528`, `dde90b3`, `86a1be8`, `b7b034a`.
Зависимости отдельной сборки теста исправлены в `237f15f`.
Перенос d2o и исправления протокольного разбора — `97931e0`;
защита приоритета пауз при упрощении — `c90eee2`.

[Как устроены шесть изменений](../algorithm-optimizations.md).
[Объём переноса d2o и дополнительные исправления](../upstream-9b74cdb.md).

## Стенд

Проверялся только стенд Keenetic/Entware ARM64. На нём оставлен DoQ;
его служба и конфигурация сохранили контрольные суммы. Основной роутер
не администрировался. Интернет стенда по-прежнему проходит через него;
по подтверждению владельца, верхний обход и отдельный Telegram-туннель выключены.
Это проверка D2S с сохранённым DoQ, не сравнение DNS-продуктов.

Установлены подписанные чистые кандидаты `0.4.0-test1` (`b7b034a`) и
`0.4.0-test2` (`97931e0`). Перед каждой установкой сохранены код, конфигурация
и состояние D2S с проверкой архивов. Резервная копия исходной установки d2o не создавалась.
MODE=apply, Telegram включён. На время испытаний AUTOUPDATE=0;
возврат исходного ночного режима выполняется после стабильного обновления.

Владелец подтвердил на обоих кандидатах новое видео YouTube с перемоткой
и отправку файлов в приложениях Telegram и WhatsApp. Telegram Web этим
результатом не проверялся и исправленным не объявляется.

## Исполнение новых приёмов

Отдельный C-инструмент собирает планы общим компилятором и использует тот же
верификатор. Кандидат ставится только на занятый им порт с отдельными случайными
Plan ID и trial ID. ACK и APPLIED связываются с этими ID, семейством, транспортом,
обоими адресами и портами. Удаление точное, подтверждено ACK до освобождения порта.
Каталог инструмент не изменяет. Штатный контроллер временно остановлен,
постоянные планы оставлены; после опыта восстановлен штатным запуском.

| Опыт на test2 | Результат |
|---|---|
| Прямой TCP-контроль | HTTP 200, полные 577 байт, имя совпало |
| Приманка перед каждой переставленной TCP-частью | APPLIED=1, отказов=0, HTTP 200/577 байт, имя совпало |
| Приманки на окно SNI между его половинами | APPLIED=1, отказов=0, HTTP 200/577 байт, имя совпало |
| Прямой QUIC-контроль | HTTP/3 200, полные 622 байта, имя совпало |
| quicsplit 2, два Initial, ClientHello 2100 байт | APPLIED=1, отказов=0, HTTP/3 200/635 байт, имя совпало |

Ошибок разбора канала управления в итоговом опыте нет. Для этой проверки
целостности протокола использован бюджет 2, не долгий поток и не объёмный
тест DPI. Производственные бюджеты не менялись. Контрольные сайты доступны
напрямую: результаты доказывают исполнение и сохранность обмена, а не обход
новой блокировки этими приёмами у конкретного провайдера.

Снимок настоящего каталога содержит контекстную историю одного плана:
IPv4/TLS1.3 — один успех и один отказ; IPv4/TLS1.2 — отдельный отказ.
Номинальная цена сохранена. Порог повторных успехов для изученного рецепта
в этом снимке не выполнен; искусственная история не добавлялась.

## Память и Discord Gateway

На самом ARM64-роутере выполнен отдельный тест 1500 искусственных циклов
allocate/run/join/reset с новым способом выделения аргументов:
VmRSS 10544 → 10608 → 10608 КиБ, VmData 10540 → 10540 → 10540 КиБ
(начало/прогрев/конец). Все отображения освобождены; ENOMEM не запускает поток.
Это память тестового процесса с подменённым сетевым измерителем, не суточный
RSS рабочего контроллера и не доказательство отсутствия любых утечек.

Для Gateway проверены 8004 JSON/мутационных случая независимым Python-разбором
и 300 Accept независимым hashlib SHA-1. Под ARM64, ARMv7 и MIPSel QEMU прошли
положительный Hello, HTTP 404, повреждённые HTTP/WebSocket/JSON, местные пределы,
nonce и отказы случайности. Отдельно фактический ARM64-бинарник d2sfetch
проверен с независимым локальным TLS1.3-сервером: четыре разных случайных nonce,
полный Hello даёт уровень приложения, 404/неверный Accept/оборванный JSON — нет.
Контрольный сертификат проверяет совпадение имени, не внешнюю цепочку доверия.

На реальном маршруте прямой запрос Gateway за 8 с не получил TLS-ответа.
Поэтому работоспособность внешнего Discord, входа в него или голоса не заявляется.

Полный HTTP-тест с очень короткими сроками и нативный RSS-порог не считаются
проверкой под QEMU: там первый упёрся в срок, второй превысил порог памяти.
Исполнительные протокольные проверки выполнены отдельно, а память проверена
нативно и на физическом роутере. Производственные сроки ради эмулятора не менялись.

## Повторный аудит

Воспроизведены и исправлены:

- Потеря STATS из-за нулевого семейства анонимного ключа. Счётчик потерь
  теперь доходит до планировщика; обычные некорректные ключи не допускаются.
- Ложный Hello при оборванном JSON, дублирующемся op или отсутствии heartbeat.
- Ложный Accept при нулевом байте, скрывавшем неверный хвост HTTP-заголовка.
- Рост реальной первой паузы при удалении перекрывающего delay/settle.
  Проверяется результат общего Plan-исполнителя, не одна номинальная цена.
- Недостающие зависимости запуска нового теста отдельно с чистого дерева.

Проверки включают полный core/datapath/detect, целевые ASan/UBSan с утечками,
историю/совместимость контекстов, поколения и чужие/повторные подтверждения,
отказы создания/присоединения работников, сохранность прежнего плана,
цельность QUIC и одно завершение каждого удержанного NFQUEUE ID.
Сетевые хуки и правила Keenetic проверяются существующими интеграционными тестами.

Общего процента ускорения, минимального возможного плана и покрытия всех
провайдеров этот прогон не измерял. Неизмеримые/местные ошибки не ухудшают
сетевой рейтинг, прямой рабочий трафик не запускает подбор, запасной путь сохранён.

## Очередь после очистки каталога владельцем

При свободном CPU 93–97% владелец увидел один активный замер и большую очередь.
Снимок API показал настоящий ограничитель: память. Доступно 44 МБ,
резерв движка — max(32 МБ, 20% от 230 МБ), то есть около 46 МБ.
Оставленные нами временные комплекты и экспорты резервных копий занимали
около 30 МБ в tmpfs. Они искажали условия проверки параллельности.

После проверки копий на ПК удалены только эти временные файлы. Памяти стало
72 МБ, лимит автоматически вырос с 1 до 13, очередь с 24 уменьшилась до нуля.
Сброшенный владельцем каталог не восстанавливался; пороги и работающие службы
ради очистки не менялись. Резервные копии D2S на ПК сохранены и проверены.

Панель ошибочно объясняла всякую очередь свободным процессором. Теперь она
показывает limited_by и соответствующую память/заполнение таблицы соединений;
объяснение обновляется даже при прежнем составе очереди. Подозрение больше
не выдаётся в заголовке за уже подтверждённую блокировку. Node-регрессии
проверяют именно этот снимок и смену причин; исправленный файл сверён с
ответом настоящей панели стенда.

## Стабильный выпуск и штатное обновление

Опубликован [D2S 0.4.0](https://github.com/shurshick/D2S/releases/tag/d2s-v0.4.0),
исходник `eca51918b131e9c48ef05739be9647c81803668a`.
Точный CI `42350742238` и выпуск `42350960666` завершились успешно.
Сборка с кэшем заняла 113 с для ARM64, 114 с для ARMv7 и 131 с для MIPSel.
В матрице выполнены 21 runtime-бинарник под QEMU и три OpenSSL smoke-теста.

Публичные архивы скачаны обратно. Проверены Ed25519, SHA256SUMS, безопасные
пути и состав архивов, точное совпадение всех установочных исходников, файлов
панели и заметок с тегом. Файлы выпуска после публикации не заменялись.

Стенд обновлён штатным подписанным updater с `0.4.0-test2` до `0.4.0`.
Минутная проверка завершилась `last_ok=true`; установленные семь программ
и шесть файлов панели совпали по SHA256 с публичным ARM64-архивом.
MODE=apply, Telegram включён, исходный AUTOUPDATE=1 восстановлен:
новые выпуски устанавливаются в 02:00–04:00 по времени роутера.
Очередь 2000, PPE v4/v6 8/8, resolver/observer работают; файлы DoQ прежние.

Старый сброшенный каталог не восстанавливался. Полные резервные копии D2S
сохранены на ПК, включая проверенные вложенные архивы, config и rollback.
Их дубликаты с `/opt` удалены перед обновлением ради места; после успеха
сам updater удалил свои распаковку, архив и временный rollback.
На накопителе осталось около 26 МБ, доступной RAM — около 66 МБ.

При финальной проверке локальная диагностика уже была включена: флаг
создан 07.11 в 02:18:46 МСК, до этой установки. Её состояние сохранено;
прежняя запись о выключенной диагностике устарела. Прикладная приёмка
остаётся подтверждением владельца на test1/test2; после stable проверены
установка, точные файлы и службы, новый ручной прогон приложений не заявляется.
