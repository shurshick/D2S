# Генерация секрета MTProto: совместимость установщика

Исходная версия: 0.5.4, source 9bce30b. Владелец сообщил остановку чистой
установки arm64 Keenetic после успешной проверки подписи и создания config.
Сообщение: «не удалось создать секрет локального Telegram-прокси».

## Воспроизведение

Реальный блок scripts/install.sh выполняется в приватном временном каталоге.
В PATH подставляется od, отвергающий параметры. До исправления тест падает
с тем же сообщением; после исправления проходит. Это воспроизведение сценария
несовместимой утилиты, а не подтверждение состава BusyBox конкретного роутера.
К роутерам не обращались.

## Исправление

Вместо od -An -N16 -tx1 /dev/urandom используется openssl rand -hex 16.
OpenSSL уже обязателен для проверки подписи/установки. Код завершения проверяется
до разбора результата, затем строго 32 строчных hex-символа. Запись происходит
только после успешной проверки; существующее значение не перезаписывается.
Не менялись runtime, криптография прокси, сетевой lifecycle и формат конфигурации.

## Регрессии

scripts/test-proxy-secret.cjs проверяет реальный блок установщика:
- несовместимый od не мешает установке;
- OpenSSL создаёт 16 случайных байт;
- секрет не выводится, config имеет права 0600;
- повторная установка сохраняет config даже с неработающим генератором;
- отказ, пустой/короткий/не-hex результат и валидный вывод с ненулевым exit
  отклоняются без записи TG_PROXY_SECRET.

Тест добавлен в GitHub integration. Изолированная полная установка использует
настоящий openssl rand вместо безусловно успешной заглушки OpenSSL.

## Первые запуски CI: внешнее ограничение

Прикладная integration-проверка source d0cd756 прошла на GitHub:
run 43042128268. Engine preparation дважды остановился до запуска тестов
при загрузке qemu-user: Temporary failure resolving azure.archive.ubuntu.com.
Пробная смена apt mirror на стандартный archive.ubuntu.com также завершилась
ошибкой DNS (run 43044379123, job 130604374334). Эта настройка не решила
проблему и удалена; требования CI, подпись и release gate сохранены.

На этом этапе выпуск 0.5.5 ещё не запускался, latest оставался 0.5.4.
Локальные тесты секрета, полный install/update/uninstall, подписанного
установщика и OpenWrt PASS. Обходной путь для уже остановленной установки:
создать отсутствующий TG_PROXY_SECRET через openssl rand -hex 16, затем
повторить штатную подписанную установку 0.5.4. Существующий ключ не менять.
Роутеры не использовались. Дальнейшее исправление и публикация описаны ниже.

## Резервное разрешение DNS в CI и выпуск 0.5.5

scripts/ci-ubuntu-dns.py запускается только root на временном GitHub runner.
При сбое системного разрешения трёх фиксированных имён Ubuntu используется
проверяемый HTTPS Cloudflare DNS JSON. Проверяются вопрос, статус, отсутствие
truncation, CNAME-цепочка, TTL и публичность IPv4. Ответы для всех нужных имён
проверяются до добавления в hosts временного runner. Исправный DNS не меняется.
Ошибка HTTPS не игнорируется; APT-подписи, TLS и release gate не отключаются.
Helper не включается в установочный пакет и не запускается на роутере.
Изолированные регрессии не используют сеть и системный hosts; helper включён
в fingerprint среды engine CI.

CI 43047815486: полный core/datapath/detect и integration PASS. В журнале
integration job 130616397540 после изолированных тестов подтверждено реальное
срабатывание HTTPS fallback для azure.archive.ubuntu.com, archive.ubuntu.com и
security.ubuntu.com. Локальная попытка HTTPS-запроса с ПК закончилась TLS timeout;
подтверждение работы в CI получено отдельно и не подменяется этим локальным опытом.

Выпуск 43051857379, source 0e06b9273e047a2172db344a10938278a77e4ac7: все четыре
сборки и QEMU PASS. Архивы скачаны обратно; подпись, суммы, состав, исходники,
release IDs и feature flags PASS. d2s-v0.5.5 опубликован stable/latest.
Квитанция: docs/field/2026-11-11-release-0.5.5.json. Роутеры не использовались.
Повторная обычная установка теперь получает исправленный подписанный комплект;
вручную создавать секрет после обновления установщика не требуется.
