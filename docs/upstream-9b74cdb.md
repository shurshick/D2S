# Перенос d2o 9b74cdb и повторная проверка D2S 0.4

Источник: [релиз d2o-20261106-2053-9b74cdb](https://github.com/t0fox/d2o/releases/tag/d2o-20261106-2053-9b74cdb),
commit `9b74cdbdef74513a14cbc1483409f5a251297834`. Сравнение с `8e2c981`
даёт два изменения: `f9669f8` (память аргументов работников) и `9b74cdb`
(Discord Gateway). Проверены все пять изменённых файлов, точки запуска,
освобождения, HTTP/TLS-вход и прежние тесты. Не импортировалось дерево целиком.

REA в сессии недоступен. Продолжен ранее разрешённый пользователем обычный
разбор исходников, сравнение и регрессионные тесты. Ручная запись анализа:
`D2S-UPSTREAM-9B74CDB-20261107`; это не идентификатор Evidence от REA.

## Что перенесено

На Linux аргументы работника получают отдельное анонимное отображение памяти;
владение заканчивается `munmap`, включая отказ создания потока. На других ОС
сохранён malloc/free. Размер стека и жизненный цикл работника не менялись.
Собственная копия изученных вопросов D2S имеет отдельное владение и учёт;
новый способ выделения аргумента её не освобождает раньше времени.
Изменение устраняет удержание этих страниц аллокатором, но не доказывает
отсутствия всех утечек или уменьшения общего RSS на конкретную величину.

Для точного имени `gateway.discord.gg` без явно заданного пути обычный HTTP
заменён запросом WebSocket Gateway v10. Успех требует HTTP 101, корректных
Upgrade/Connection/Accept и полного Hello. HTTP 404 больше не подтверждает
работоспособность Gateway. Обычные сайты и запросы ресурсов идут прежним путём.
Проверяется анонимное открытие Gateway, без токена, Identify, входа в аккаунт
или отправки сообщений. Это не проверка Discord целиком и не проверка голоса.
HTTP keep-alive бюджет к этому обмену не применяется; пройденным он не отмечается.

## Исправления поверх исходника

- Разбор исходника принимал `{"op":10` без конца JSON, дубли `op`, лишний хвост
  и отсутствие данных Hello. Это воспроизведено отрицательными тестами.
  Теперь проверяется весь JSON, единственный корневой `op: 10`, объект `d`
  и положительный целый `heartbeat_interval`. Вложенный op не заменяет корневой.
  Проверяются разделители, числа, UTF-8, escape и пары суррогатов.
- Вместо постоянного примера nonce используется 128 бит случайности на опыт.
  Accept вычисляется для этого запроса. SHA-1 применяется только к публичному
  WebSocket-преобразованию key24+GUID36, не для доверия сертификату или подписи.
- Уточнены строка статуса и канонические длины WebSocket. Серверный masked-кадр,
  RSV и неверный Accept не дают успеха. Неподдержанный первый фрагмент/контрольный
  кадр остаётся местным ограничением реализации, а не отказом кандидата.
- Буфер заголовка+первого кадра ограничен 4096 байт, вложенность JSON — 32.
  Их превышение помечается `local_limit`, отсутствие случайности —
  `local_refusal`. Они не становятся отрицательным знанием о сети.

## Найденная на стенде ошибка счётчиков

При независимой проверке новых TCP/QUIC-приёмов найден старый дефект D2S:
событие STATS отправлялось с полностью нулевым ключом, а клиент отвергал
семейство 0 до чтения счётчика потерь. Планировщик не получал `dropped_seen`.
Это собственное исправление D2S, не часть переноса 9b74cdb.

Датапат теперь отправляет канонический анонимный ключ с семейством 4.
Клиент также понимает прежний строго нулевой ключ только у STATS. Нулевое
семейство обычного потока или STATS с заполненными адресами по-прежнему
отвергается. Регрессия на реальный прежний формат упала до правки и прошла
после неё. Проверки потери событий в ранжировании/обучении/обслуживании сохранены.

## Проверки и границы

Проверяются 1500 циклов worker allocate/run/join/reset, равенство отображённых
и освобождённых байтов и ENOMEM без запуска потока. Прежние проверки отказа
pthread_create/join, поколений и владения изученными вопросами сохранены.
Положительные/отрицательные WebSocket-ответы подаются частями настоящему
читателю. Отдельный тест компилирует сами C-функции и сравнивает 8004 случая
JSON с независимым Python-разбором и 300 Accept с hashlib SHA-1.
Это лабораторные проверки. Результаты сборки, санитайзеров, стенда и публикации
фиксируются отдельно, по факту завершения.

## Reviewed engine changes

- core/sched.c: отображение/освобождение аргументов, собственные вопросы и
  прежний жизненный цикл D2S сохраняются; шесть алгоритмических изменений
  описаны в algorithm-optimizations.md.
- core/verify.c: точный Gateway-вход, запрос, полный разбор ответа и местные
  ограничения; остальные протоколы/пути не заменены.
- core/test_sched_worker_lifecycle.c, core/test_sched_summary.c,
  core/test_verify_http.c: адаптированные регрессии источника и проверки D2S.
- core/link.c, core/test_link.c, datapath/d2sd.c: собственное исправление STATS
  с ограниченной совместимостью анонимного старого формата.
