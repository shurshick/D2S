# D2S на OpenWrt

Нативная установка не требует Entware. Проверяемый стенд — OpenWrt 25.12.6
x86_64, VirtualBox, штатные fw4/nftables и dnsmasq. ARM64/ARMv7/MIPSel входят
в сборку, но испытания именно OpenWrt на этих физических роутерах ещё нужны.

## Установка и управление

Нужен root, интернет, доступные пакеты для установленного ядра и OpenSSL 3
для проверки Ed25519. Пакеты ставятся штатным apk/opkg; не устанавливайте
модули от другого ядра. OpenWrt 22.03 с OpenSSL 1.1.1 не поддерживает текущую
команду проверки подписи. В ходе работ VM обновлена с 22.03.5 до 25.12.6;
этот переход не считается миграцией пакетов D2S.

```sh
(f=$(mktemp) && wget -q -O "$f" https://raw.githubusercontent.com/shurshick/D2S/main/install.sh && sh "$f"; r=$?; [ -z "${f:-}" ] || rm -f "$f"; exit "$r")
```

Панель: `http://адрес-роутера:8090/`. Только LAN: аутентификации пока нет.
Автозапуск — `/etc/init.d/d2s`; рабочие файлы — `/opt/d2s`, программы —
`/opt/sbin`. `/opt` на OpenWrt создаётся самим D2S.

```sh
/etc/init.d/d2s restart
/opt/etc/init.d/S99d2s status
/opt/etc/init.d/S99d2s update-check
/opt/etc/init.d/S99d2s update-install
```

Ночные установки — 02:00–03:59 по часам роутера. Если `/opt` находится
на корневой файловой системе, рабочий архив и временный откат обновления
хранятся в `/tmp/d2s-update`. Подпись и SHA256 обязательны; после установки
службы проверяются минуту. Не удаляйте временный откат во время обновления.

## Сеть и DNS

- D2S использует собственные таблицы nftables рядом с fw4. Правила переживают
  перезагрузку firewall; при удалении снимаются только таблицы D2S.
- Flow offloading fw4 отключается на время работы, иначе очередь пропускает
  часть потока. При остановке исходное значение восстанавливается. Пропускная
  способность может оказаться ниже, чем с ускорением.
- Наблюдатель DNS выбирает клиентские сети по зонам-источникам forwarding,
  доверенным зонам без masquerade и включённым DHCP-серверам; устройства
  определяются через netifd. Статический LAN с выключенным DHCP тоже подходит.
  Адреса и имена Linux-интерфейсов не зашиты. После добавления нового LAN
  перезапустите D2S для обновления списка устройств наблюдателя.
- Поддерживается штатный dnsmasq с `addn-hosts=/tmp/hosts`. Для иного DNS
  нельзя молча считать замену адреса работающей: такой backend требует
  отдельной адаптации. Несовместимая конфигурация выдаёт отказ помощника.
- TLS-проверенные альтернативные адреса записываются в отдельные файлы
  `/tmp/hosts/d2s-*.tsv`; сохранённая принадлежность записей находится в
  `/opt/d2s/state`. При запуске свои записи восстанавливаются. Чужие hosts
  не переписываются, удаляется только собственная точная пара имя/адрес.

IPv6 сохраняется в основном nft-тракте; отдельная проверка маршрутизации IPv6
на этой VM пока не выполнена. Медиа-DNS-помощник работает с IPv4-записями.

## Удаление

Полное удаление, включая настройки и найденные решения:

```sh
curl -fsSL https://raw.githubusercontent.com/shurshick/D2S/main/scripts/uninstall.sh -o /tmp/d2s-uninstall.sh && D2S_KEEP_STATE=0 sh /tmp/d2s-uninstall.sh
```

Удаление программ с сохранением настроек и изученного каталога:

```sh
curl -fsSL https://raw.githubusercontent.com/shurshick/D2S/main/scripts/uninstall.sh -o /tmp/d2s-uninstall.sh && D2S_KEEP_STATE=1 sh /tmp/d2s-uninstall.sh
```

## Что проверено

На VM: запуск семи программ и панели, штатное подписанное обновление wire21→22
через локальный HTTPS-стенд с доверенным тестовым CA, отрицательная проверка
изменённой подписи, независимый клиент в network namespace за NAT, полные
HTTPS-ответы при обоих Timestamp-профилях, QUIC/HTTP3 200 с полным ответом,
добавление/восстановление/удаление DNS-записи с сохранением чужой записи,
удаление с сохранением конфигурации и повторная подписанная установка.
Каталога с изученными стратегиями в этой чистой VM не было: его сохранение
проверяется отдельно изолированным установочным тестом.

Эти проверки не доказывают обход у конкретного провайдера, исправление
Telegram Web или работу Discord voice. VM выходит через основной шлюз;
настройки основного роутера не менялись. Публичный выпуск 0.5.0 установлен штатным updater и обычной командой быстрого
старта; после перезагрузки все службы поднялись, хеши совпали с архивом GitHub.
Временная лабораторная сеть и TLS-fixture удалены, автообновление включено
на обычный канал. [Сводка проверки](field/2026-11-07-openwrt-c38.json).
