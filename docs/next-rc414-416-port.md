# D2S 0.5.10: исправления Next rc4.14–rc4.16

База D2S 242d324 (стабильный 0.5.9), источник локального Next
002a478. Перенесён диапазон после 1675be1: 5ccac15, fef50d2, 8d50a51,
ffc2580, 9459cdf, 9eb408b, e40a98b, 879e364, 3b212ef, 002a478.
Исправления прочитаны по исходникам и сверены с фактическим D2S; ранее
разрешённый владельцем перенос без недоступного REA. Это статический разбор
и локальные регрессии, не доказательство работы браузера/роутера.

## HTTPS и подтверждение

В D2S отсутствовала prerequisite-ветка транспортного свидетельства Next.
Перенесены outcome.c и отдельная ограниченная проверка именно этого случая:
полный аутентифицированный 400/401/403/404/429/451/5xx либо корректный HTTPS
redirect 301/302/303/307/308, без challenge/известного портала/локального лимита,
без ECH и измеренного обрыва данных. Адрес перенаправления не загружается.

Кандидат требует совпавший APPLIED с прежним trial/execution/flow-контекстом
и два сопоставимых прямых контроля того же endpoint, собственного TLS-профиля,
Timestamp-контекста, сжатия и пути, по bypass-mark. Два TLS-отказа подтверждают
только восстановление транспорта; рабочий прямой TLS запрещает подтверждение.
Локальный отказ/неполный контроль не считается блокировкой. Сохраняется
verified_by=PROBE_HANDSHAKE, в панели явно сказано, что приложение не проверено.
Такая привязка не обучает семейство и не запускает минимизацию.

Это выборочный перенос: обычная ветка успешного прикладного обмена D2S и
QUIC-производитель не заменены всей архитектурой/политикой Next. Два новых
контроля выполняются только для перечисленных транспортных свидетельств,
не являются постоянными фоновыми запросами. Их счёт включён в диагностику.

## Контроллер и QUIC

- Linux runtime использует pthread_tryjoin_np: stop запрошен, но цикл не ждёт
  сетевой системный вызов. Данные задачи и её дескрипторы остаются во владении
  до успешного join; повторная попытка через 10 мс. Shutdown явно дожидается
  потоков. Фикстуры синхронных алгоритмов ждут явно, lifecycle-тесты продолжают
  тики, проверяя живой цикл, а не прежнюю блокировку.
- Active учитывает все занятые фазы, включая contact/settle/voice.
- По окончании срока незавершённого поиска применяется существующий 10-минутный
  cooldown того же endpoint. Это не отрицательное обучение и не очистка каталога.
- Собранный ClientHello уточняет UNKNOWN/TLS1.2/TLS1.3/ECH и Timestamp-профиль.
  Уже пропущенная голова не обрабатывается планом задним числом.
- Рост обратного conntrack-счётчика продлевает наблюдение долгого потока.
  Просто живая запись без прогресса не удерживает память. Тест: 5 минут,
  IPv4/IPv6, позднее подозрение при перемотке ровно один раз, затем idle expiry.
- Повтор hello не устраняет доказанный data cut. Привязки с таким ограниченным
  доказательством не обучают CDN-семейства. Старые точные записи/история остаются;
  старое QUIC-семейство из replay-only не ставится без трёх прикладных имён.
  Дополнительно исправлена область проверки: replay чужого домена с тем же
  plan_id не влияет на другое семейство (отдельный RED/GREEN тест).
- Hold остаётся 100 мс; добавлены single/multi timeout и максимальная просрочка
  освобождения. Deferred retirement называется отменой завершённого/заменённого
  потока, а не доказанным пропуском срока отправки.

## Telegram

Первичный WSS admitted-клиента приоритетнее спекулятивного второго маршрута.
Потенциальным клиентам в ожидании handshake/DNS резервируются первичные слоты.
Ресурсы обновляются раз в 5 с по MemAvailable/RSS/буферам/живым FD: снижение
немедленное, рост после двух образцов ограниченными шагами. Ранее выделенные
буферы и admitted-клиенты не отзываются. Warm Worker pool уменьшается при
давлении. Сохранён предел из конфигурации обычного D2S, включая ручной; старт
ограничен 32 клиентами. Журнал изменений лимитов ограничен минутой, ноль и
восстановление пишутся немедленно, текущие числа доступны в stats.

Worker framing/path задаются до асинхронного DNS. Победитель гонки маршрутов
восстанавливает selected transport после отмены соседей; первый ответ отмечается
только если реально распознан. Обработка reserved-first-byte abridged применяется
только к проверенному transparent DC без endpoint secret; локальный MTProto
проходит прежнюю секретную аутентификацию первым. Telegram Web passthrough,
секреты, мост шифрования, Worker rate limits и балансировка D2S сохранены.
Удалённый код Worker этим выпуском не развёртывается.

## Проверки и границы

RED до production-порта: test_quic_lifetime терял активный поток; test_session
оставлял UNKNOWN после полного приветствия. GREEN после. Отдельные тесты
проверяют transport proof на 108 IPv4/IPv6 early/late APPLIED комбинациях,
неподходящие trial IDs, рабочий прямой TLS, статусы и framing/challenge guards;
возврат tick <200 мс при 500 мс остановке worker, ownership/join failure,
1500 циклов workers; границы и cooldown, сохранность подтверждённой привязки.

Панель/супервизор Next, новое оформление и Wire 23 не переносились. Wire 22,
firewall, NFQUEUE recovery, обучение/исключения на диске и автозапуск сохранены.
Роутеры не использовались. Лабораторное прохождение не доказывает исправление
перемотки YouTube, запуска iPhone или конкретного сайта в поле.

Локально PASS: outcome/status/redirect guards; 108 CDN trial-контекстов;
worker lifecycle (1500 циклов), default deadlines/cooldown/active count;
QUIC lifetime, session capture и hold; весь Telegram test/san; ASan/UBSan
для outcome, scheduler summary/algorithms/workers и packet session/hold/lifetime;
нативная сборка controller и panel test/test-js. Длинная общая регрессия
выполняется отдельно на точном выпускаемом SHA.

Дополнительный guard: аутентифицированный отказ сервера, не подходящий даже
как transport witness (например, при data cut/challenge), не подтверждает
приложение или общую приманку. При завершении partial path контроллер не
обращается к сброшенному контексту и сохраняет cooldown исходного endpoint.
Старый 403-fixture обновлён под эту семантику; отдельный тест покрывает reset.
