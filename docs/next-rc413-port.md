# Перенос исправлений D2S Next rc4.13 в D2S 0.5.9

Источник: локальный D2S Next 1675be150ee4ed8bbf19008d514400e8aaed2cac,
коммиты d13d7fe, 84c7ec3, 93b06db, 1675be1. База D2S: 82903b3.
Перенос выбранных изменений, без Wire 23 и архитектуры Next.

## Основание и границы

В диагностике Next поиск signaler-pa.clients6.google.com занимал 621189 мс,
из них 603665 мс классификатор (121 проба). easylist-downloads.adblockplus.org
после полных 404 переставал отвечать на 7–9-й повторный HTTP-запрос.
Это не локализует отказ в DPI: возможна политика keep-alive сервера.
46 QUIC-привязок имели доказательство повтора hello, а не работы приложения.
Эти наблюдения не доказывают ту же причину для rutor.org/Instagram/rutracker.

## Изменения

- HTTP/TCP и HTTP/3: молчание на повторный запрос после завершённых ответов
  -> NOT_APPLICABLE, а не CUT. Полнота предыдущего ответа сохраняется.
  Настоящие неполные тела, RX-пары и исходные критерии подтверждения не изменены.
- Политика измерений по умолчанию: 90 с текущего классификатора, 180 с всего
  активного TCP/QUIC-поиска, включая перезапуски фаз. Очередь не расходует
  время до первого worker. Голос, наблюдение и припаркованный QUIC исключены.
  Это явная перенесённая политика против измеренного многоминутного занятия
  слота, по текущему поручению владельца; не новый критерий сетевой блокировки.
- Завершение -> inconclusive/time-limit; кооперативный stop/join, снятие только
  своего кандидата, повторная синхронизация сохранённых планов. Не создаётся
  отрицательное обучение или новый QUIC deny. Не очищает каталог/исключения.
- Внутренний API search_limits допускает явную прежнюю 10-минутную политику
  (0/0). UI, конфиг и Wire не расширяются. Тесты старого жизненного цикла
  выбирают её явно; отдельные тесты проверяют новую политику по умолчанию.
- level_name учитывает verified_by=5/6: TLS/hello не выдаются за успех приложения.
  Панель уже использует эту строку API; числа и идентификаторы не изменены.

## Проверки и ограничения

Новый test_verify_budget упал на исходном D2S (assert budget), после исправления
прошёл: timeout/EOF/закрытие и полноценный пакетный бюджет, повтор HTTP/3.
Summary проверяет границы 90/180 с, перезапуск, голос, парковку, настоящий
pthread stop/join, inconclusive и побайтовую сохранность подтверждённой привязки.
Большой scheduler-fixture выделяется в heap, не в стеке санитайзера.

Предел времени не жёсткий realtime: join ждёт выхода текущей ограниченной
сетевой операции. Не добавлены фоновые запросы/зависимости. Память: два int
на scheduler и clock flag + два int64_t на задачу (с выравниванием).
Telegram/WhatsApp, firewall, автозапуск и подписанные обновления не меняются.
Роутеры не трогали, открытие сайтов/приложений этим переносом не подтверждено.

Локально PASS: test-verify-budget, test-sched-summary, test-sched-algorithms,
test-verify, test-volume-context; ASan/UBSan для budget/summary; panel test/test-js;
reviewed-source guard, namespace и полнота CI-shards (78 check / 56 san).
Полная регрессия и четыре подписанных runtime-пакета проверяются CI выпуска.

Первый полный CI выявил три прежних ожидания CUT в test_verify_http для
молчания на следующий запрос. Они изменены на NOT_APPLICABLE; сценарий
реально незавершённого ответа QUIC по-прежнему требует CUT. Это дополнительные
существующие HTTP-fixture D2S, не удаление проверок.
