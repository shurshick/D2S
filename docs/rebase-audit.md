# Аудит и новая база D2S 0.2.0

Дата: 2026-11-04. База: t0fox/d2o fd4e262. Прежний D2S: bc62147, архив archive/d2s-0.1.3.

## Вывод

В прежнем D2S изменялись не алгоритмы подбора, а условия попадания пакетов в них. В S99d2s добавлялись RETURN по отрицательному совпадению с d2s_lan4; доступность правил зависела от успешного чтения NDM и обнаружения сегментов. PPE также ограничивался этим набором, а IPv6 исключался. Это подтверждённые различия исходников, но причиной отказа YouTube на основном роутере они экспериментально не доказаны: пользователь запретил использовать его для тестов. Исправление выбранной архитектуры — восстановление исходного сетевого тракта.

## Проверенные границы и решения

| Область | Решение 0.2 |
|---|---|
| core, detect, datapath | Все C/H исходники побайтно совпадают с fd4e262. 275 файлов вместе с двумя firewall helpers защищены манифестом SHA-256. |
| S99d2s / NFQUEUE / политики / DNS исключения | Исходные функции d2o. Изменены только запуск/остановка дополнительных DNS-служб и аргумент вывода версии. |
| PPE | Исходный d2s-ppe-deoffload.sh без LAN-фильтра и запрета IPv6. |
| Telegram redirect | Исходный d2s-tg-firewall.sh: IPv4/IPv6, PREROUTING/OUTPUT, mark исключения исходящих соединений прокси. |
| Telegram proxy | epoll_proxy.c и тесты уже включают upstream 150bcf7; не накладывать тот же патч повторно. Наш main.c добавляет Meta media hosts для WhatsApp. |
| NDM netfilter hook | Исходный 001-d2s.sh. Дополнительный refresh наблюдателя из старого D2S не переносится. |
| WhatsApp | Локальный C resolver на loopback, пассивный наблюдатель DNS, проверка сертификата точного медиадомена, учёт и удаление только собственных пар hostname/IP. |
| LAN discovery | Только выбор интерфейсов пассивного DNS-наблюдателя. Не участвует в NFQUEUE, PPE или Telegram redirect. |
| Установщик | Подпись, архитектура, запас RAM, staging и сохранение конфигурации; дополнения WhatsApp устанавливаются отдельно. Их отказ запуска не блокирует запуск основного движка. |
| Обновление | Собственный ключ D2S, 02:00–03:59 по времени роутера, rollback. Release notes передаются в подписанные metadata и проверяются до публикации. |
| Панель | Сохранены тема D2S, canvas, доступность reduced motion и исправление перекрытия счётчиков. |
| История | Ветка main заменяется новой линией от d2o; старый код доступен в архивной ветке. |

## Метод и ограничения

Проанализированы diff всех отслеживаемых файлов, изменения runtime, установка/удаление, подпись, lifecycle и пакетирование. REA-инструменты в этой сессии не доступны (проверен каталог инструментов); Evidence REA отсутствует. Основание выводов — git diff, побайтовая сверка исходников, изолированные тесты и отдельный журнал стенда. Это не доказательство отсутствия всех ошибок в upstream.

Стенд: 192.168.31.1; основной роутер 192.168.1.1 не опрашивается и не изменяется. Стенд выходит через основной шлюз, на котором работает d2o/keenetic-doq: успешный YouTube за стендом не доказывает обход именно стендом. Нельзя менять шлюз для устранения этого влияния без отдельного разрешения. Прикладные проверки сообщений, файлов, видео и звонков следует отличать от исправности процессов и наличия правил.

## Полевой результат

Пользователь отключил основную сеть 192.168.1.1 и подтвердил выход в интернет через стенд: YouTube работает; отправка в Telegram и WhatsApp работает. Это прикладное подтверждение на ARM64, не доказательство конкретной причины отказа старой версии и не проверка всех моделей/протоколов. Скачивание файлов WhatsApp, звонки и IPv6 приложений отдельно не подтверждены.

На стенде установлен keenetic-doq (S56doqd, 5354 TCP/UDP). После перехода на официальный подписанный пакет d2s-v0.2.0 проверка updater завершилась last_ok=true; основной движок, Telegram, resolver и наблюдатель живы. NFQUEUE привязана, PPE: 8/8 IPv4 и 8/8 IPv6. Старых ссылок d2s_lan4 / D2O_TG_LAB / d2o_tg_lab4 в iptables нет. DNS youtube.com через стенд отвечает.

Изолированные проверки: firewall bookkeeping S99, nft/iptables Telegram, updater (подпись/rollback/окно 02–04), семь сценариев LAN discovery, пять сценариев Meta media, 12 HTTP resolver сценариев и hostile DNS parser — PASS. Telegram и panel test/test-js — PASS. Datapath check и detect check — PASS. Все 21 бинарник ARM64/ARMv7/MIPSel запускаются под QEMU, архивы прошли проверку SHA-256/состава/RAM и Ed25519. Другие физические архитектуры не проверены.

Полный `make -C core check ZIG=...` завершился успешно, включая группы scheduler, cross-link ARM64/MIPSel/MIPS, QUIC/HTTP runtime и диагностику. GitHub D2S checks и release 41878701902 завершены успешно.
