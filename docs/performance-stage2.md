# Ускорение классификатора: второй этап

База — стабильный D2S 0.3.2, исполняемый код d7792a7, рабочая точка b0d6f80.
В первом этапе пример TCP-поиска занял 19,6 с, из них 18,3 с — классификация.
Это не измеренное время одного конкретного вопроса. Повторная инвентаризация
05.11 обнаружила также два завершившихся поиска googlevideo на 146/158 зондов
и 873/961 с. Сокращать все сроки из этих чисел нельзя: нужны ответы вопросов.

## Изменения

- Длинный разрез определяет свойство пересборки по условию «успехов нет» /
  «есть хотя бы один успех». После первого положительного ответа оставшиеся
  повторы этого вопроса не меняют результат и теперь не выполняются. Все три
  отрицательных ответа, фактически наблюдённые ошибки и отмена сохраняют прежнюю обработку.
- Ответное направление TLS 1.2 сохраняет три целевых рукопожатия. Его текущий
  критерий контрольного имени — `control > 0`, поэтому контроль прекращается
  после первого успеха. Полностью отрицательный контроль проверяется трижды.
  Это не требование трёх успешных контролей: раньше решение также принималось
  по одному успеху из трёх. Теперь счётчик содержит реально заданные вопросы.
- Локальное превышение буфера, фактически обнаруженное до завершения вопроса,
  по-прежнему означает «не измерено», а не блокировку. Незаданные после
  достаточного ответа пробы не считаются ни успехом, ни отрицательным ответом.
- Время каждого завершённого вопроса публикуется в CLI `--json` / `--progress`
  как `elapsed_ms`; это монотонное время вместе с сетевыми ожиданиями, не CPU.
  Добавлены отдельные строки `response:target` и `response:control`, фактический
  счётчик проб ответного направления вместо прежних безусловных `2 × repeats`.
  Повторно использованная база имеет нулевую новую стоимость. Локальная ошибка
  ответного направления помечается в трассе, не скрываясь за отрицательным счётом.
  Вложенные `transport:*` входят во время родительского вопроса: складывать
  все строки трассы для получения общего времени нельзя.

Общие сроки подключения/ответа, три повтора базового вопроса, большинство
свойств, единогласие подтверждения плана, параллелизм и правила сетевого
перехвата не меняются. Длинный отрицательный запасной перебор этим этапом
не устранён. Telegram Web — отдельная задача.

## Reviewed engine changes

- `detect/classify.c`: достаточный ответ длинного разреза, время наблюдений,
  трасса и фактическая стоимость ответного направления.
- `detect/response.c`: раннее завершение только положительного контроля,
  фактические повторы и время двух сторон, тестовая подмена рукопожатия.
- `detect/props.c`: завершение наблюдения через общий измеритель времени.
- `detect/include/d2s_detect.h`: поля времени и стоимости локальных результатов;
  сетевой протокол контроллер/датапат не меняется.
- `detect/main.c`: дополнительные поля CLI без изменения выбора стратегии.
- `detect/test_repeats.c`, `detect/Makefile`: регрессии ранней остановки и включение
  нового `test_response_repeats` в полный `check` и очистку.

Побайтовая сверка неизменённого ядра сохранена. Для этих файлов в
`tests/keenetic/audited-engine-changes.json` закреплены точные хеши файлов,
входящих в закреплённую базу; Makefile и новый тест проверяются обычным CI.

## Проверки и границы

До правки регрессии обнаружили три длинных разреза вместо одного и лишние
контрольные рукопожатия. После правки проходят 64 комбинации измеренных
положительных/отрицательных ответов с сохранением итогового вердикта и
целевых повторов. Проверены локальные ошибки до достаточного ответа,
положительный длинный разрез на первом/втором/третьем повторе, три промаха,
ошибка отправки, фактическая трасса, транспортное восстановление и отмена.
Время повторно использованной базы не засчитывается ещё раз.

Полный `make -C detect check` прошёл на Linux, новые проверки повторов также
с ASan/UBSan. ARM64-классификатор собран и запущен под QEMU.
[Полевое сравнение](field/2026-11-05-performance-stage2.md): два соединения
сняты в каждом проверенном прямом поиске; общий CI записывается после завершения.
Ускорение отдельной ветки нельзя выдавать за процент ускорения всего подбора.
