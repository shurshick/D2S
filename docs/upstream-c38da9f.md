# TCP-профили и семейные правила: перенос d2o 07.11.2026

Источник: [d2o-20261107-1106-c38da9f](https://github.com/t0fox/d2o/releases/tag/d2o-20261107-1106-c38da9f),
коммит `c38da9ffb51e4160bdc4aa7d72e278a1394a0177`.
Сравнение с уже перенесённым `9b74cdbdef74513a14cbc1483409f5a251297834`:
семь коммитов, 23 файла. Последний коммит меняет только статусы панели;
основные изменения находятся перед ним.

## Объём переноса

- Профиль TCP Timestamp сохраняется из совпадающего клиентского потока.
  Позднее закрытие связывается с первым потоком-триггером, а не последним
  произвольным снимком такого же имени.
- Проверки, привязки каталога и семейные правила различают TCP с Timestamp
  и без него. UDP/QUIC сохраняет свой прежний контекст. Неизвестный профиль
  не считается доказанным совпадением.
- Неудачное применение профиля запускает перепроверку совместимого варианта;
  повтор для одного варианта не подавляет восстановление другого.
- Старые точные привязки без профиля сохраняются: исключение семейства не
  должно случайно выключать такую работающую запись.
- Панель различает подтверждение плана на доменах, установку общего правила
  и отсутствие связи с датапатом. Установка правила не доказывает успех сайта.

Протокол управления — **wire 22**. Контроллер и датапат обновляются вместе.
Не заменять один бинарник вручную. Старый каталог читается без миграции;
новое поле `tcp_profile` допускает только 0, 1, 2.

## Стыки с D2S

Сохранены все шесть улучшений 0.4, строгий разбор Gateway, случайный nonce,
доставка STATS, возврат памяти работников и собственная панель.
Трёхстороннее сравнение потребовало разрешить только конфликт списка ключей
тестового планировщика; обе группы тестов сохранены.

Фоновое упрощение D2S дополнительно ограничено тем же TCP-профилем и сохраняет
его в новой привязке. Регрессия воспроизводит принятие чужого профиля без
этого ограничения, затем проверяет оба независимых опыта и сохранённый контекст.
Контакт классификатора также получает профиль задачи, а не только конечный
верификатор кандидата. Не состоявшийся локальный контакт не является ответом DPI.

## Проверки и пределы

Полные локальные core/datapath/detect и целевые алгоритмические проверки прошли.
На настоящем ядре VM OpenWrt 25.12.6 x86_64 общий C-коннектор создал четыре
соединения без Timestamp и четыре с ним. `TCP_INFO` подтвердил согласованные
опции; после каждого обращения исходный sysctl восстановлен.

В Linux нет обычного socket-option для такого выбора SYN. Как в источнике,
коннектор кратко меняет `net.ipv4.tcp_timestamps` вокруг `connect()` и
восстанавливает прежнее значение до ожидания ответа. Mutex защищает потоки
этого процесса, но не чужие процессы в том же network namespace. Полного
отсутствия влияния на чужой одновременный SYN этот тест не доказывает.
Запрет записи/ошибка восстановления отмечается локальным отказом, не блокировкой.

Дополнительная проверка удалённого узла выявила дефект исходника: при исходном
sysctl=0 запрос профиля Timestamp возвращал успешный connect, но установленное
соединение оставалось без Timestamp. На loopback это скрывалось быстрым SYN-ACK.
В D2S вариант отклоняется локально до SYN: временно включать Timestamp поверх
выключенного namespace недостаточно для такого измерения. После любого
профильного connect фактические опции также проверяются через TCP_INFO.
Если сервер не согласовал Timestamp, это тоже не считается нужным профилем.

Оба дефекта воспроизведены на VM: удалённый публичный контроль и отдельный
сервер без Timestamp за veth дали расхождение на старом коннекторе; новый
возвращает локальную недоступность, сохраняя sysctl. Автотест проверяет исходные
значения 0/1/2 в отдельном network namespace. Это не включает Timestamp
самовольно в пользовательской конфигурации.

Через отдельный клиентский namespace за VM прошли полные HTTPS-ответы при
обоих профилях и QUIC/HTTP3. Это проверка исполнения/маршрутизации, не доказательство
прохождения конкретной блокировки или исправления Telegram Web/Discord voice.

REA в сессии недоступен. Продолжено ранее разрешённое владельцем ручное сравнение,
чтение связанных модулей и регрессионные проверки. Запись анализа:
`D2S-UPSTREAM-C38DA9F-20261107`; это не идентификатор REA Evidence.
